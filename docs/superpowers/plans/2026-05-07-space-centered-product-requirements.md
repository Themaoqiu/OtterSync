# Ottersync 空间功能与 UI 完善需求文档

> 本文档用于整理当前这一轮需要补完的功能与界面要求。目标是先把完整的空间功能实现出来，再在此基础上完善整体 UI 与动画表现。

## 1. 总体目标

当前软件中，凡是已经有预留接口的组件，都应当视为有对应功能需要真正实现，而不是继续保留占位状态。

本轮工作分成两个阶段：

1. 先实现完整的空间功能
2. 再完善整体 UI 和交互动画

整个软件要逐步从“前端演示页面”变成“基于真实数据库数据驱动的可用产品”，因此页面中的内容、空间、任务、摘要、面板、日历等都应当使用真实动态数据，而不是继续依赖前端写死的测试内容。

## 2. 空间创建功能

### 2.1 新建空间弹窗形式

- 新建空间的 UI 不能再是普通居中弹窗。
- 新建空间应当改为“从下往上弹出”的底部弹窗。
- 整体交互要现代 Flutter / Jira 风格。

### 2.2 新建空间字段

新建空间时需要支持以下内容：

- 空间名称
- 空间模板
- 空间 key

其中：

- 当前空间模板先只需要支持 `看板`
- 空间 key 需要根据空间名称自动生成

### 2.3 空间 key 自动生成规则

空间 key 需要是 2 到 4 个大写字母，并且要尽量可读。

示例要求如下：

- 如果空间名称叫“毛球”，则 key 可以生成 `MQMQ`
- 如果空间名称叫“智能终端开发课程设计”，则 key 可以生成 `TANK`
- 如果当前存在一个 `ottersync` 空间，它的 key 是 `OT`

这个 key 不只是数据库字段，也要直接参与首页展示。

例如：

- 空间 key 为 `OT`
- 那么主页显示的对应入口名称应当是 `OT面板`
- 可以手动指定，也能自动生成，填入空间名称后就在key输入框自动生成，但是还能手动改成其他值

也就是说，首页上显示的面板名称要与空间 key 直接对应，而不是继续展示写死的名称。

### 2.4 空间头像生成

每个空间都需要自动生成一个头像。

头像要求：

- 由一个背景和一个彩色 icon 组成
- 效果要尽量随机
- 不同空间之间尽量不要重复

这里的重点不是上传真实头像，而是自动生成一个有辨识度的空间图标系统。

## 3. 首页功能要求

### 3.1 恢复 AI 创建工作项入口

- 主页上原来“利用人工智能创建工作项”的入口需要加回来
- 这个入口要一直显示
- 不能因为当前是否有数据而隐藏

### 3.2 快速访问区域调整

- 首页中的快速访问区域需要继续保留
- 但展示内容要与真实空间数据绑定
- 各个面板入口名称要基于空间 key 动态显示，例如 `OT面板`

### 3.3 已查看 / 动态 budget 区域

在快速访问下方，需要新增一个 `已查看 / 动态` 的 budget 区域。

这个区域的作用：

- `已查看`：显示用户已经查看过的工作项
- `动态`：显示最近新建的工作

交互要求：

- 两个状态之间可以切换
- 切换时要有 Flutter 自带的、比较美观的动画
- 不要手搓很重的自定义动画
- 应当优先参考 Flutter 官方推荐的动画实现方式

### 3.4 我的工作筛选器

- 首页需要补回“我的工作筛选器”
- 样式和交互要参考你提供的图
- 这个模块不是静态展示，而是需要真的能进入对应筛选结果或工作视图

### 3.5 首页样式需要调整

- 首页整体样式要随着上述模块调整而一起优化
- 在增加“已查看 / 动态”区域和“我的工作筛选器”后，页面结构应当更完整、更像真实产品首页，而不是简单卡片堆叠

## 4. 顶栏与滚动行为要求

### 4.1 顶栏必须固定

每个页面的顶栏都需要固定住。

要求是：

- 往下滑动时
- 顶栏不要和 body 的内容一起滚动

### 4.2 当前已知问题

当前至少有两个地方不符合要求：

- 首页顶栏的头像会和页面内容一起滑动
- 新建工作页的顶栏也会和页面内容一起滑动

这两个问题都需要修正。

最终效果应当是：

- 顶栏固定
- 内容单独滚动
- 页面结构更稳定

## 5. 空间入口与跳转

### 5.1 从首页或空间页进入空间

对于空间：

- 无论是在首页
- 还是在空间页面

点击任意一个空间之后，都应当跳转到对应空间的看板页面。

这里的跳转目标，不应当是演示页面或占位页面，而应当是该空间的真实详情页面。

### 5.2 空间页面参考样式

空间页面的整体方向参考：

- `/Users/themaoqiu/CodeRepo/Android/ottersync/style/Screenshot_20260414_154018_Jira.jpg`

也就是说，进入空间后，用户应当看到一个完整的空间工作台，而不只是简单的摘要列表。

## 6. 空间详情页要求

### 6.1 空间详情页需要展示真实动态数据

空间详情页中的摘要部分需要显示真实动态数据，而不是前端写死的统计值。

摘要里展示的数据应当来自真实数据库中的空间和工作项。

### 6.2 顶部选择栏

空间详情页最上面的选择栏，除了摘要之外，还应当能够切换以下视图：

- 面板
- 日历
- 待办事项列表
- 报告
- 设置

也就是说，进入空间后不只是看摘要，而是要具备一个完整的多视图工作空间。

相关风格可以参考：

- `/Users/themaoqiu/CodeRepo/Android/ottersync/style/Screenshot_20260414_154052_Jira.jpg`

### 6.3 索引报错问题

当前空间详情页点进去会出现：

- `the query requires an index`

这个问题必须改成实际可用。

要求不是简单地隐藏错误，而是：

- 页面真的能正常查询数据
- 页面真的能正常展示内容

## 7. 面板功能要求

### 7.1 面板页面形态

面板页面参考：

- `/Users/themaoqiu/CodeRepo/Android/ottersync/style/Screenshot_20260414_154032_Jira.jpg`

当空间中还没有被加入面板的工作时，面板可以显示空页面。

但这个空页面不是最终状态，一旦有工作被加入面板，就应当切换成真实工作展示。

### 7.2 从待办事项列表加入工作到面板

在待办事项列表中，需要能够把工作添加到面板中。

添加后应满足：

- 面板不再显示空页面
- 面板显示实际工作内容

也就是说，面板和待办事项列表之间需要有真实联动关系。

## 8. 两类工作项要求

系统里需要明确存在两类工作：

### 8.1 普通待办

第一类是普通待办：

- 来源于主页右上角添加的工作
- 这类工作不一定一开始就在面板里

### 8.2 冲刺工作

第二类是冲刺工作：

- 是已经被放进面板里显示的工作

### 8.3 两类工作项的统一管理

这两类工作都需要：

- 在待办事项列表里进行查看和管理
- 并且在待办事项列表中通过两个卡片进行区分和管理

换句话说，待办事项列表里不能只展示一种工作形态，而要能把普通待办和冲刺工作都组织起来。

## 9. 日历功能要求

### 9.1 两类工作都能进入日历

普通待办和冲刺工作都应当可以在日历页面安排时间。

也就是说：

- 普通待办可以进入日历
- 冲刺工作也可以进入日历

### 9.2 日历样式

日历页面的样式参考你已经给出的两张日历图。

这意味着日历页不只是一个简单日期占位页，而应当是一个真正可以承载工作安排的视图。

## 10. 实现顺序要求

本轮开发顺序明确如下：

1. 先实现完整的空间功能
2. 再完善 UI

这里所说的“完整的空间功能”至少包括：

- 创建空间
- 进入空间
- 空间摘要
- 空间顶部视图切换
- 面板
- 待办事项列表
- 日历
- 报告
- 设置
- 空间与任务的真实联动

## 11. UI 与动画要求

### 11.1 所有页面都要补动画

在完善 UI 的阶段，页面不只是静态排版调整，还要补足合适的 Flutter 动画。

### 11.2 动画实现方式

要求是：

- 优先查看 Flutter 官方文档
- 学习 Flutter 官方推荐的动画实现样式
- 尽量使用官方推荐能力
- 不要自己手搓一套风格很重、维护成本高的动画系统

重点场景包括但不限于：

- 底部弹窗出现与关闭
- 首页 `已查看 / 动态` 的切换
- 页面区块切换
- 面板空状态到有数据状态的过渡
- 列表或卡片内容切换

## 12. 这一轮最终目标

这一轮最终不是只修一个页面，而是把软件中围绕“空间”这一核心实体的功能链路做完整。

最终效果应当是：

- 可以创建空间
- 空间能自动生成 key 和头像
- 首页能基于真实空间显示动态入口
- 用户能从首页或空间页进入真实空间
- 空间里有摘要、面板、日历、待办事项列表、报告、设置
- 工作项有普通待办和冲刺工作两种形态
- 两种工作都能被查看、管理、加入面板并进入日历
- 页面整体 UI 更完整，动画更自然，顶栏滚动行为正确
