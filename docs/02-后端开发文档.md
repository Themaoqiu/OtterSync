# OtterSync 后端开发文档

## 1. 后端目标

OtterSync 后端用于支撑移动端项目协作应用，核心能力包括项目与任务管理、工作区与群组权限、AI 智能辅助、报表分析、通知、审计和文档归档。

当前仓库只有 Flutter 前端原型，后端尚未实现。本文档给出可落地的后端开发方案，接口与数据结构应优先满足现有前端页面和业务流程图中的需求。

## 2. 推荐技术栈

| 层级 | 推荐方案 | 说明 |
| --- | --- | --- |
| API 服务 | Spring Boot 3 或 NestJS | 均可实现 REST API，团队可按熟悉程度选择 |
| 数据库 | MySQL 8 | 适合课程项目和管理信息系统场景 |
| 缓存 | Redis | 保存会话、热点列表、限流计数 |
| 认证 | JWT + Refresh Token | 移动端接入简单 |
| 文件存储 | 本地存储或对象存储 | 用于附件、报表、测试文档、复盘文档 |
| 异步任务 | 定时任务 + 消息队列可选 | 用于通知、报表生成、AI 调用 |
| API 文档 | OpenAPI/Swagger | 便于前后端联调 |

如课程范围较小，可先实现单体后端：`Controller -> Service -> Repository -> Database`，后续再拆分模块。

## 3. 业务模块

| 模块 | 职责 | 对应前端页面 |
| --- | --- | --- |
| Auth | 登录、刷新令牌、退出登录、当前用户信息 | 账户中心、全局请求 |
| User | 用户资料、成员列表、用户偏好 | 账户中心、空间成员 |
| Workspace | 工作区、组织配置、成员邀请 | 空间、账户中心 |
| Space/Project | 空间/项目创建、配置、统计 | 空间、空间详情 |
| Issue | 工作项创建、查询、状态流转、指派、优先级、截止日期 | 主页、所有工作、待办列表 |
| Sprint/Backlog | Sprint、待办分组、看板数据 | 空间详情待办、面板 |
| Filter | 默认筛选器、用户自定义筛选器 | 所有工作 |
| Dashboard | 指标汇总、活动流、绩效进度分析 | 仪表板、空间摘要 |
| Notification | 通知、提醒、已读状态 | 通知页 |
| AI Assistant | 智能问答、项目/空间生成、摘要、复盘草稿 | 主页今日概述、AI 业务流程 |
| Report | 项目报告、成员绩效、复盘总结、归档 | 仪表板、流程图业务4 |
| Audit | 操作日志、权限变更日志、安全审计 | 后端通用能力 |

## 5. 通用开发规范

### 5.1 接口规范

统一响应格式：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "traceId": "req-20260422-000001"
}
```

分页响应格式：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 100,
  "hasNext": true
}
```

### 5.2 错误码规范

| 错误码 | HTTP 状态 | 说明 |
| --- | --- | --- |
| `OK` | 200 | 成功 |
| `BAD_REQUEST` | 400 | 参数错误 |
| `UNAUTHORIZED` | 401 | 未登录或令牌失效 |
| `FORBIDDEN` | 403 | 无权限 |
| `NOT_FOUND` | 404 | 资源不存在 |
| `CONFLICT` | 409 | 状态冲突或重复提交 |
| `VALIDATION_FAILED` | 422 | 字段校验失败 |
| `INTERNAL_ERROR` | 500 | 服务端异常 |

### 5.3 命名规范

- 数据库表名使用小写下划线，例如 `issues`、`work_logs`。
- API 路径使用复数名词，例如 `/api/v1/issues`。
- DTO 使用场景命名，例如 `CreateIssueRequest`、`IssueDetailResponse`。
- 状态字段统一使用英文枚举值，前端负责显示中文。

### 5.4 权限规范

权限判断分为三层：

| 层级 | 说明 |
| --- | --- |
| 登录权限 | 是否携带有效 Token |
| 工作区权限 | 是否属于工作区成员 |
| 资源权限 | 是否有项目、工作项、报表、设置等具体操作权限 |

建议角色：

- `OWNER`：工作区拥有者。
- `ADMIN`：工作区或空间管理员。
- `MEMBER`：普通成员。
- `VIEWER`：只读成员。
- `EXTERNAL`：外部协作者。

## 6. 核心业务开发说明

### 6.1 项目与任务管理

来源于业务流程图“项目与任务管理”：

1. 项目经理创建项目。
2. 设置项目目标、需求、优先级、截止日期。
3. 项目负责人拆解任务并指派。
4. 开发人员执行任务、更新进度、提交工时。
5. 测试组验证。
6. 任务完成后归档并生成复盘资料。

后端需实现：

- 项目/空间 CRUD。
- 工作项 CRUD。
- 工作项状态流转：`TODO -> IN_PROGRESS -> IN_REVIEW -> TESTING -> DONE`。
- 工时记录。
- 测试结果记录。
- 操作日志和状态历史。

### 6.2 工作区与群组管理

来源于业务流程图“工作区与群组管理”：

- 创建工作区/站点。
- 配置组织信息和权限。
- 创建群组。
- 分配项目角色。
- 设置通知规则。
- 成员加入群组并协作。

后端需实现：

- 工作区成员邀请。
- 群组管理。
- 角色权限矩阵。
- 成员可见资源计算。
- 权限变更审计日志。

### 6.3 AI 智能辅助

来源于业务流程图“AI 智能辅助”和用例“用户进行智能问答与检索”。

后端需实现：

- AI 对话会话。
- 用户问题解析。
- 项目/任务/文档数据检索。
- 生成回复、摘要、模板或项目创建建议。
- AI 输出留痕，便于审计与复盘。

AI 能力可以先做规则模拟，后续再接入真实大模型。

### 6.4 报表分析

来源于业务流程图“Dashboard/Analytic & Reporting”和用例“查看绩效与进度分析”“生成复盘总结报告”。

后端需实现：

- 项目摘要指标。
- 状态分布和优先级分布。
- 成员工时、任务完成率、进度偏差。
- 活动流聚合。
- 复盘报告生成与归档。

## 7. 开发优先级

建议按以下顺序开发：

1. Auth、User、Workspace 基础能力。
2. Space/Project 和 Issue 基础 CRUD。
3. 工作项查询、筛选器、待办列表。
4. 仪表板指标、通知和活动日志。
5. 报表归档、复盘报告。
6. AI 问答、AI 摘要、智能创建项目/任务。

## 8. 测试要求

| 测试类型 | 覆盖范围 |
| --- | --- |
| 单元测试 | Service 业务规则、状态流转、权限判断 |
| 集成测试 | Controller + Database |
| 接口测试 | 登录、空间、工作项、仪表板、通知 |
| 权限测试 | 不同角色访问资源 |
| 异常测试 | 参数错误、无权限、资源不存在、重复提交 |

关键用例必须覆盖：

- 非成员不能访问工作区资源。
- 只读成员不能创建或修改工作项。
- 工作项不能从 `DONE` 随意回退，除非有管理员权限。
- 工时记录异常时标记为待审批。
- 报表生成失败时保留失败原因。
