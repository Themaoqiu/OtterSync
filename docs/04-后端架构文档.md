# OtterSync 后端架构文档

## 1. 架构目标

OtterSync 后端架构需要支撑四条主业务线：

- 项目与任务管理。
- 工作区与群组管理。
- AI 智能辅助。
- 仪表板、绩效分析与复盘报告。

当前建议采用模块化单体架构，便于课程项目快速开发、部署和演示。后续如果业务量增加，可按模块拆分为微服务。

## 2. 总体架构

```text
Flutter App
    |
    | HTTPS / REST JSON
    v
API Controller Layer
    |
    v
Application Service Layer
    |
    +--> Auth/User Service
    +--> Workspace/Group Service
    +--> Space/Project Service
    +--> Issue/Sprint Service
    +--> Dashboard/Report Service
    +--> AI Assistant Service
    +--> Notification Service
    +--> Audit Service
    |
    v
Domain Repository Layer
    |
    +--> MySQL
    +--> Redis
    +--> File Storage
    +--> AI Provider
```

## 3. 分层职责

| 层级 | 职责 |
| --- | --- |
| Controller | 接收 HTTP 请求、参数校验、返回统一响应 |
| Application Service | 编排业务流程、事务控制、权限校验 |
| Domain Service | 实现核心业务规则，如任务状态流转、工时审批 |
| Repository | 数据库读写 |
| Integration | 文件、AI、通知、外部系统集成 |
| Audit/Event | 记录审计日志，发布通知和活动事件 |

## 4. 模块架构

### 4.1 认证与用户模块

职责：

- 登录、刷新令牌、退出登录。
- 获取当前用户资料。
- 保存用户偏好，如主题模式。

关键输出：

- JWT Access Token。
- Refresh Token。
- 当前用户上下文。

### 4.2 工作区与权限模块

职责：

- 创建工作区。
- 邀请成员。
- 管理成员角色。
- 管理群组。
- 校验资源访问权限。

权限模型：

```text
用户 -> 工作区成员 -> 工作区角色 -> 空间角色 -> 资源操作权限
```

所有业务操作进入 Service 前，应先完成权限校验。

### 4.3 空间与项目模块

职责：

- 创建空间/项目。
- 配置空间类型：Scrum、看板、通用。
- 查询空间列表、最近访问空间、空间详情。
- 统计空间摘要指标。

前端对应：

- 空间页。
- 空间详情页。
- 主页快速访问。

### 4.4 工作项与 Sprint 模块

职责：

- 创建、查询、更新工作项。
- 指派经办人。
- 设置优先级、截止日期。
- 管理 Sprint 和待办分组。
- 记录状态历史和工时。

状态流转：

```text
TODO -> IN_PROGRESS -> IN_REVIEW -> TESTING -> DONE
TODO -> CANCELED
IN_PROGRESS -> TODO
TESTING -> IN_PROGRESS
```

测试未通过时，任务可从 `TESTING` 回到 `IN_PROGRESS`。

### 4.5 仪表板与报表模块

职责：

- 生成首页摘要。
- 生成空间摘要指标。
- 统计状态分布和优先级分布。
- 生成成员绩效和进度分析。
- 生成复盘总结报告。

数据来源：

- 工作项。
- 工时。
- 状态历史。
- 评论和协作记录。
- AI 分析结果。

### 4.6 AI 智能辅助模块

职责：

- 接收用户自然语言问题。
- 解析意图。
- 检索项目、任务、文档、日志。
- 生成回答或创建建议。
- 将确认后的建议回写到项目/空间/工作项。

AI 调用建议采用“人工确认后执行”：

```text
用户提问 -> AI 生成建议 -> 用户确认 -> 后端执行创建/更新 -> 写入审计日志
```

这样可以避免 AI 直接修改业务数据造成风险。

### 4.7 通知与活动模块

职责：

- 工作项指派通知。
- 状态变更通知。
- 报表生成完成通知。
- AI 建议完成通知。
- 活动流聚合。

通知可以先同步写入数据库，后续再扩展 WebSocket 或移动推送。

### 4.8 审计模块

职责：

- 记录成员、权限、工作项、报表、AI 操作。
- 支持管理员查看审计日志。
- 支持异常行为追踪。

审计日志不参与业务回滚，建议独立保存。

## 5. 业务数据流

### 5.1 项目与任务管理

```text
项目经理创建项目
-> 项目负责人拆解任务
-> 开发人员执行任务并提交工时
-> 测试组验证
-> 任务完成
-> 工时与状态进入报表统计
-> 复盘文档归档
```

### 5.2 工作区与群组管理

```text
管理员创建工作区
-> 配置组织和权限
-> 创建群组
-> 邀请成员
-> 成员加入项目/频道
-> 协作记录进入日志和 AI/报表数据源
```

### 5.3 AI 智能辅助

```text
用户发起聊天
-> AI 解析意图
-> 查询项目/任务/文档数据
-> 生成回复或建议
-> 用户确认后回写业务系统
-> 结果进入审计和报表
```

### 5.4 报表分析

```text
用户打开仪表板
-> 后端聚合任务、工时、成员、状态、AI 数据
-> 生成摘要、图表、活动流
-> 用户查看或导出
-> 报表归档并生成通知
```

## 6. 安全架构

| 安全点 | 方案 |
| --- | --- |
| 身份认证 | JWT Access Token + Refresh Token |
| 接口访问 | Controller 层拦截未登录请求 |
| 资源权限 | Service 层校验工作区和空间权限 |
| 敏感数据 | 报表和 AI 输出做脱敏处理 |
| 审计 | 关键操作写入 `audit_logs` |
| 限流 | 登录、AI 问答、报表生成接口限流 |
| 文件安全 | 校验文件类型、大小、访问权限 |

## 7. 非功能要求

| 项目 | 要求 |
| --- | --- |
| 响应时间 | 常规列表接口 500ms 内，复杂报表可异步生成 |
| 可用性 | 后端异常时返回统一错误结构 |
| 可维护性 | 模块化目录，Controller 不写业务逻辑 |
| 可扩展性 | AI、报表、通知可以异步化 |
| 可观测性 | 请求日志、错误日志、审计日志、traceId |
| 数据一致性 | 工作项状态、工时、报表快照在事务中处理 |

## 8. 部署架构

课程项目最小部署：

```text
Flutter App
    |
Nginx / HTTPS
    |
Backend App
    |
MySQL
```

增强部署：

```text
Flutter App
    |
Nginx / API Gateway
    |
Backend App
    +--> MySQL
    +--> Redis
    +--> File Storage
    +--> AI Provider
```

## 9. 架构演进建议

第一阶段：单体后端，实现认证、空间、工作项、筛选器和仪表板。

第二阶段：引入通知、审计、报表归档和文件上传。

第三阶段：接入 AI 服务，实现智能问答、摘要、复盘报告草稿。

第四阶段：将 AI、报表、通知拆为异步任务，提升性能和稳定性。
